# 07 · 环境传感器（AHT20 + BMP280）

读底板上的温湿度与气压。三个 I2C 器件（AHT20、BMP280、MPU6050）挂在同一条总线上，
本工程只碰前两个，MPU6050 留给 04/05/06。

## 硬件

| 器件 | 类型 | 地址 | 说明 |
|---|---|---|---|
| AHT20 | 温湿度 | `0x38` | 固定地址 |
| BMP280 | 气压 + 温度 | `0x77` | 由 SDO 引脚决定，两个地址都探测 |
| MPU6050/6500 | 六轴 | `0x68` | 同总线，本工程不使用 |

**这块底板上 BMP280 实测在 `0x77`**（SDO 拉高），不是常见的 `0x76`。驱动里两个地址都会探，
不用改代码。

| 信号 | 引脚 |
|---|---|
| SDA | GPIO8 |
| SCL | GPIO9 |
| WS2812 | GPIO48 |

这条是**传感器总线**（GPIO8/9）。排针上另有一条 I2C（GPIO41/42）给 OLED 用，
两者不是同一条，混接会互相干扰。

## 输出

每 2 秒一行，串口直接给物理量。实机读数示例（室温环境）：

```
I (857) AHT20: status=0x08 calibrated=1
I (867) BMP280: ready at 0x77  chip id=0x58  dig_T1=27900 dig_P1=37814
I (957) MAIN: AHT20   temp=24.68 C   humidity=74.1 %
I (1007) MAIN: BMP280  temp=24.92 C   pressure=1019.94 hPa
```

两颗片子的温度差 0.24 ℃，可以互相印证读数是否可信。气压 1019.9 hPa 对应海平面附近的高压天气。

板载 WS2812 同步显示温度：**蓝 = 冷，红 = 暖**，色标两端是 15 ℃ 和 32 ℃
（`main.c` 的 `LED_COLD_C` / `LED_WARM_C`）。没有显示器也能一眼看出读数是否合理。

## 启动时会扫描总线

`app_main` 里第一件事是 `i2c_bus_scan()`，把 0x08–0x77 逐个探一遍：

```
I (312) I2C: scanning bus ...
I (330) I2C:   0x38  AHT20
I (340) I2C:   0x68  MPU6050
I (350) I2C:   0x76  BMP280
I (360) I2C: 3 device(s) found
```

这一步是排线问题的第一道筛子：如果器件没焊、没插好或者接错总线，这里就会直接暴露，
不用去猜驱动哪里写错了。什么都没扫到时会打印应检查的引脚。

## 驱动要点

**AHT20 是命令式的，不是寄存器式的。** 每次测量都要先发 `0xAC 0x33 0x00` 触发转换，
等 80 ms（代码留了 90 ms 余量），再读 7 字节：第 1 字节是状态位，
`bit7` 是忙标志，`bit3` 是校准标志。温湿度各占 20 位，打包跨越 6 个字节——
湿度是 `[1][2][3]高4位`，温度是 `[3]低4位[4][5]`，两段共用一个字节。

上电后必须先发 `0xBE 0x08 0x00` 做一次校准，否则读数会漂。初始化里还先发了
`0xBA` 软复位，并且上电后等了 40 ms——这颗片子刚上电时有一段不接受命令的时间。

**BMP280 是寄存器式的。** `0xD0` 读型号（`0x58` 才是 BMP280），
`0x88` 起 26 字节是出厂校准系数，`0xF4` 控制过采样与模式，`0xF7` 起 6 字节是测量结果。

补偿用数据手册的整数算法（`bmp280.c` 的 `compensate_temperature` / `compensate_pressure`），
不转成浮点中间量。气压结果的单位是 Q24.8 帕（每帕 256 个计数），所以除以 256 再除以 100 得到 hPa。
注意气压补偿依赖温度补偿产生的 `t_fine`，两者必须按顺序算，所以 `s_t_fine` 是文件级静态变量。

本工程用**强制模式**（`0xF4 = 0x55`）：每次读之前触发一次转换，等 50 ms 再取，
而不是让它在后台自由运行。配合 2 秒的轮询周期，既省电又不会读到过期数据。

## 排错

- **扫不到 0x38**：AHT20 没焊或没插。注意它是 4P 排针位，可能只是没插上。
- **扫到 0x76 但读不出气压**：先看型号对不对，`chip id` 不是 `0x58` 的会直接报错退出。
  BME280 也常见，它型号是 `0x60`，寄存器布局不同，本驱动不支持。
- **湿度恒为 0 或 100**：多半是没做初始化校准，看启动日志里的 `calibrated=0`。
- **气压偏差几十 hPa**：检查是否读到了完整的 26 字节校准区，漏读会导致系数错位。
- **总线挂死**：两个 I2C 总线不要混接，GPIO8/9 和 GPIO41/42 是独立的。
